# Engineering Trade-offs

## Monolith Instead of Microservices

A Rails API and React frontend are sufficient for the current product and
10,000-employee scale.

Microservices would introduce deployment, networking, observability, and
data-consistency complexity without a demonstrated requirement.

## Offset Pagination

The employee directory uses LIMIT/OFFSET pagination.

For 10,000 employees this is simple and adequate. At substantially larger
scale, cursor-based pagination could be considered.

## Bulk Seed Inserts

The seed script uses insert_all! for efficient generation of 10,000
employees and salary records.

Bulk inserts bypass ActiveRecord callbacks and validations, which is
acceptable because the seed dataset is generated by controlled application
code.

Normal API writes continue to use model validations.

## Currency Conversion

Automatic currency conversion is intentionally excluded.

Exchange-rate conversion requires decisions about rate providers,
historical rates, reporting currency, and conversion dates.

Instead, analytics are grouped by currency.

## Authentication

Authentication and authorization are outside the initial assessment scope.

A production salary system should implement secure authentication,
role-based authorization, audit logging, and appropriate controls for
sensitive compensation information.
